# Auth Service

`auth-service` — микросервис Training Center Platform, отвечающий за регистрацию, аутентификацию, JWT и управление доступом пользователей.

## Возможности

- регистрация пользователя;
- вход по электронной почте и паролю;
- выдача JWT Access Token;
- получение данных текущего пользователя;
- обновление данных текущего пользователя;
- удаление собственной учётной записи;
- роли `STUDENT`, `TEACHER`, `ADMIN`;
- ролевое ограничение доступа;
- блокировка и разблокировка пользователей администратором;
- изменение роли пользователя администратором;
- получение списка пользователей с пагинацией, сортировкой и фильтрацией;
- удаление одного пользователя администратором;
- массовое удаление пользователей с ролью `STUDENT`;
- PostgreSQL и Liquibase;
- Swagger/OpenAPI с Bearer JWT.

## Технологии

- Java 21
- Spring Boot
- Spring Web

- PostgreSQL

## Основные endpoint'ы

### Аутентификация

```text
POST /api/auth/register
POST /api/auth/login
GET  /api/auth/me
PATCH /api/auth/me
DELETE /api/auth/me
```

### Администрирование

В сервисе предусмотрены административные операции для управления пользователями:

- получение списка пользователей;
- изменение роли;
- блокировка и разблокировка;
- удаление пользователя по идентификатору;
- массовое удаление пользователей с ролью `STUDENT`.

Точные пути и параметры endpoint'ов можно посмотреть в Swagger после запуска сервиса.

## JWT

После успешного входа сервис выдаёт Access Token.

Для обращения к защищённым endpoint'ам необходимо передавать:

```text
Authorization: Bearer <access-token>
```

Refresh Token в проекте не используется.

Секрет JWT задаётся через переменную окружения:

```text
JWT_SECRET
```

## Роли

Используются роли:

```text
STUDENT
TEACHER
ADMIN
```

Новый пользователь при обычной регистрации получает роль `STUDENT`.

## Обновление текущего пользователя

Текущий пользователь может изменить свои профильные данные через:

```text
PATCH /api/auth/me
```

Если изменяется электронная почта, необходимо использовать новый Access Token, возвращённый сервисом.

## Удаление пользователей

Пользователь может удалить собственную учётную запись.

Администратор дополнительно может:

- удалить конкретного пользователя;
- удалить всех пользователей с ролью `STUDENT`.

Операции администратора не должны затрагивать его собственную учётную запись там, где это запрещено бизнес-логикой сервиса.

## Swagger

После запуска:

```text
http://localhost:8085/swagger-ui/index.html
```

Для проверки защищённых endpoint'ов:

1. выполнить регистрацию;
2. выполнить вход;
3. скопировать `accessToken`;
4. нажать `Authorize` в Swagger;
5. передать JWT;
6. выполнить защищённый запрос.


База:

```text
auth_db
```

Порт:

```text
5437
```

## Разделение ответственности

`auth-service` является источником данных, связанных с аутентификацией и авторизацией:

- учётные данные;
- пароль;
- роль;
- состояние блокировки;
- JWT;
- операции изменения и удаления учётной записи.

`user-service` используется как сервис профилей и предоставляет профильные данные для чтения.

Синхронизацию профильных данных между `auth-service` и `user-service` через Kafka планируется реализовать отдельными учебными задачами.
